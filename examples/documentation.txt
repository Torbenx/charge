-- Variable kinds: let, var, in, inout, out.
   Where the 'let' and 'var' apply to all variables and the others only to parameters.
-- 'let' is the default and can be omitted.

-- A

           | in    | inout | out   | var
   --------|-------|-------|-------|-------
    unique | no    | yes   | yes   | yes
    shared | yes   | yes   | no    | no

-- Initialized at begin/end:

    let        | in/inout | out    | var
   ------------|----------|--------|---------
    yes*/undef | yes/yes  | no/yes | yes*/no

   *The initialization of block 'let' and 'var' variables can be deferred.

-- Types of assignment: initialize, replace, value
    var rect: Rect = ...;
    rect.left() = ...;           // ok
    rect.bottomLeft().x = ...;   // ok
    rect.bottomLeft().x() = ...; // impossible because the result of 'bottomLeft()' cannot be bound to the 'inout self' parameter of 'x() = '

-- Only parameter declarations and can have constraint on them. These are not constraints of the variable but only of its initial value.
-- By default all parameters are constraint to contract fulfilling values, so there needs be a way to lift that restriction. Examples:
    fn test(irregular e: Enum);     // This has some nice symmetry with parameter kinds that contract initialization state requirements.
    fn test(decontracted e: Enum);  // So does this, but in longer. However it has 'contract' in it.
    fn test(e: decontracted(Enum)); // This makes it a property of the type and suggests there to be a type that the same except for the
                                    // 'std::contract' trait implementation. Such a type could be useful in some situation, but is a
                                    // property of variable and not just the initial value.
    fn test(irregular e ?out(std::regular): Enum)

    - assume: The condition is not checked and assumed to true.
